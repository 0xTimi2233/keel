# 学习记录格式规范 (Learning Record Format)

学习记录保存在 `./learning-records/` 目录中，并使用顺序编号：`0001-slug.md`、`0002-slug.md` 等。惰性创建该目录 — 仅在写入第一条记录时创建。

它们是软件开发中 ADR (架构决策记录) 在教学领域的对应物：它们捕获非显而易见的教训、关键见解以及表明的先验知识，用以指导未来的教学环节。它们用于计算最近发展区 (zone of proximal development)。

## 模板

```md
# {所学内容或所确立认知的简短标题}

{1-3 句话：学习到了什么（或确立了什么先验知识），以及为什么它对未来的教学环节很重要。}
```

这就是完整的格式。一条学习记录可以只有单个段落。其价值在于记录*某些认知已被掌握*以及*为什么*它会改变接下来要教授的内容 — 而不在于填满各个章节。

## 可选章节

仅在它们能带来真实价值时包含这些章节。大多数记录不需要它们。

- **Status** frontmatter (`active | superseded by LR-NNNN`) — 当早期的理解被证明是错误的并被取代时很有用。
- **Evidence**（证据） — 用户如何证明了该理解（回答的问题、完成的练习、引用的先验经验）。当结论可能被重新审查时很有用。
- **Implications**（影响/推论） — 这为未来的环节解锁了什么或排除了什么。当非显而易计时值得记录。

## 编号规则

扫描 `./learning-records/` 以获取现有的最大编号，并加 1 递增。

## 何时编写学习记录

当满足以下任何一项时编写一条学习记录：

1. **用户展示了对非平庸事物的真正理解** — 不仅仅是接触过，而是有证据表明他们能够正确使用该概念。这为接下来要教授的内容设定了新的基线。
2. **用户透露了先验知识** — “我以前就知道 X。” 记录下来，以便未来的环节不会重复教授。同时记录声明的*深度*。
3. **纠正了误区** — 用户以前认为某个错误观点，现在明白了原因。这些记录价值极高：它们能预测相关主题日后可能遇到的障碍。
4. **使命随着学习发生转变** — 用户发现他们关心的内容与他们原先设想的不同。交叉链接到 [[MISSION.md]] 并予以更新。

### 哪些*不*符合条件

- 仅仅是覆盖过的材料。覆盖不等于掌握。等待证据。
- 已经在 [[GLOSSARY.md]] 中作为术语定义精炼捕获的任何内容。不要重复。
- 逐环节的活动日志。学习记录不是日记 — 它们是决策级别的见解。

## 替换与废弃 (Supersession)

当后期的记录与早期的记录相抵触时（用户的理解加深或得到纠正），将旧记录标记为 `Status: superseded by LR-NNNN`，而不是直接删除它。理解演进的历史本身就是有用的信号。
