Skill 的存在是为了从随机/概率系统 (stochastic system) 中梳理出确定性 (determinism)。**可预测性 (Predictability)** — 代理在每次运行中采取相同的*流程*，而不是产生相同的输出 — 是核心美德；下文中的每个杠杆都为其服务。

**加粗的术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中有定义；在其中查找它们以获取完整含义。

## 调用 (Invocation)

两种选择，权衡不同的成本：

- **模型调用 (model-invoked)** 的 Skill 保留 **description**，以便代理可以自主触发它，*并且*其他 Skill 可以触达它（你仍然可以输入其名称）。它会增加**上下文负载 (context load)** — 描述在每一轮对话中都停留在窗口中。机制：省略 `disable-model-invocation`，并编写面向模型的描述，附带丰富的触发短语（“在用户想要……、提及……时使用”）。
- **用户调用 (user-invoked)** 的 Skill 从代理的可达范围内去除了描述：只有你输入其名称才能调用它 — 且没有其他 Skill 可以调用它。零上下文负载，但它会消耗**认知负载 (cognitive load)**：*你*是必须记住它存在的索引器。机制：设置 `disable-model-invocation: true`；`description` 变为面向人类的 — 一行摘要，删去触发词列表。

仅在代理必须自行触达该 Skill，或者另一个 Skill 必须触达它时，才选择模型调用。如果它除了手动之外从不触发，将其设置为用户调用且不付出上下文负载。

当用户调用的 Skill 激增超出你能记住的范围时，堆积起来的认知负载可以通过一个**路由 Skill (router skill)** 来解决：一个用户调用的 Skill，负责命名其他 Skill 以及何时触达每一个。

## 编写描述 (Writing the description)

模型调用的**描述 (description)** 承担两项工作 — 声明 Skill 是什么，并列出应该触发它的**分支 (branches)**。每一个词都会增加**上下文负载**，因此描述比正文更值得无情剪枝：

- **在前头部放置 Skill 的主导词** — 描述是它发挥调用效用的地方。
- **每个分支一个触发词。** 重命名单条分支的同义词属于**重复 (duplication)** — “使用 TDD 构建功能……要求测试驱动开发”是被重写了两次的单条分支。折叠它们；仅保留真正明确区分的分支。
- **剪掉正文中已有的身份声明。** 保持描述仅包含触发词，加上任何“当另一个 Skill 需要……时”的触达条款。

## 信息层级 (Information hierarchy)

Skill 由两种自由混合的内容类型构建 — **步骤 (steps)** 和 **参考 (reference)**：Skill 可以是全步骤、全参考或两者兼有。核心决策是使用哪一种，以及每一种在**信息层级**上的位置，梯子按代理需要材料的紧迫程度排名：

1. **Skill 内步骤 (In-skill step)** — `SKILL.md` 中的有序动作，主层级：代理按顺序做什么。每个步骤终止于一个**完成标准**，即告知代理工作已完成的条件。使其*可检查*（代理能否区分完成与未完成？）且在关键之处使其*完备*（“核对每个修改过的模型”，而不是“生成一个变更列表”） — 模糊的标准会诱发**提前完成 (premature completion)**。
2. **Skill 内参考 (In-skill reference)** — `SKILL.md` 中按需查阅的定义、规则或事实。通常是合法平铺的同级集合（审查的每条规则都在一个横木上） — 一个良好的编排，而不是坏味道。*本 Skill 全是参考。*
3. **外部参考 (External reference)** — 被推离 `SKILL.md` 到独立文件中的参考，通过**上下文指针**触达，仅在指针触发时加载。（涵盖*公开暴露*的参考 — 同级文件如 `GLOSSARY.md`，依然是 Skill 的一部分 — 一直到完全的**外部参考**，存在于 Skill 系统之外且任何 Skill 都可以指向它。）

要求高的完成标准可以驱动彻底的**底层调查工作量 (legwork)** — 代理在工作内部进行的深挖 — 无论 Skill 是否包含步骤，因为“应用每条规则”与“完成每个步骤”对序列的约束一样约束平铺参考。

向下推的内容太少，顶部会膨胀；向下推的内容太多，你会隐蔽代理实际需要的材料。这种张力就是整个决策。

**渐进式暴露 (Progressive disclosure)** 是在梯子上向下移动的操作 — 从 `SKILL.md` 移入链接文件 — 以保持顶部清晰易读。机制：Skill 文件夹中链接的 `.md` 文件，以其承载的内容命名（本 Skill 将其完整的定义公开暴露到 `GLOSSARY.md`）。某些 Skill 以多种方式使用，每种不同的方式都是一个**分支 (branch)** — 不同的运行采取穿过 Skill 的不同路径。分支是最干净的暴露测试：内联每条分支都需要的内容，将仅某些分支触达的内容推到指针背后。**上下文指针**的*措辞*（而不是其目标）决定了代理何时以及多可靠地触达材料。

在梯子决定片段*下沉多深*的地方，**同置归集 (co-location)** 决定到达该处后*什么放在其旁边*：将某个概念的定义、规则和注意事项保持在一个标题之下，而不是散落放置，以便阅读一部分连带阅读其相邻内容。

## 何时拆分 (When to split)

**粒度 (Granularity)** 是你划分 Skill 的精细程度，每次切口都会消耗两种负载之一，因此仅在切口物有所值时才拆分。两条切口：

- **按调用拆分** — 当你有一个明确的**主导词**应该独立触发它，或者另一个 Skill 必须触达它时，拆分出一个**模型调用**的 Skill。你为新的始终加载的**描述**付出了**上下文负载**，因此独立触达必须值得这一付出。
- **按序列拆分** — 当未来的步骤（步骤的**后置步骤**）诱使代理匆忙对待眼前的步骤（**提前完成**）时，拆分一系列**步骤**。保持它们不可见可以鼓励代理在当前任务上进行更多**底层调查工作量**。

## 剪枝与修剪 (Pruning)

将每个含义保存在**单一事实来源**中：一个权威位置，因此修改行为是在一处进行编辑。

检查每一行的**相关性**：它是否依然与 Skill 所做的事相关？

然后逐句搜寻**无操作 (no-ops)**，而不仅仅是逐行：对单句孤立运行无操作测试，当一句测试失败时，删除整个句子，而不是精简其中的词汇。要果断 — 大多数测试失败的散文应该直接删掉，而不是重写。

## 主导词 (Leading words)

**主导词 (leading word)** 是模型预训练中已存在的精炼概念，代理在运行 Skill 时用它来进行思考（例如 _lesson_、_fog of war_、_tracer bullets_）。在整个文本中重复（尽管不一定需要大量重复 — 一个强有力的主导词可能只需要出现一次），它累积了一个分布式定义，并通过招募模型已持有的先验知识，用最少的 token 锚定了整块行为区域。

它两次服务于可预测性。在正文中，它锚定了*执行*：每次该词出现时，代理都会采取相同的行为。在描述中，它锚定了*调用*：当同一个词保存在你的提示词、文档和代码中时，代理会将该共享语言连接到 Skill，并更可靠地触发它。

搜寻重构 Skill 以使用主导词的机会。在三处拼写出的三元组（**重复**）、用一个句子对手势表示某个想法的描述 — 每一个都是渴望**折叠 (collapse)** 为单个 token 的段落。示例包括：

- “快速、确定、低开销” -> _tight_ — 跨阶段重述的一个质量 — 折叠为单个预训练词汇（一个 _tight_ 循环）。
- “一个你信任的循环” -> _red_ — 将模糊门禁转换为二进制可观察状态（循环在 Bug 上变 _red_，或者没有）。

你获得了双重胜利：更少的 token，*以及*代理挂载其思考的更尖锐的钩子。假设每个 Skill 都承载着主导词可以退役的重述 — 去找到它们。

## 失败模式 (Failure modes)

使用这些来诊断用户在使用 Skill 时可能遇到的问题。

- **提前完成 (Premature completion)** — 在步骤真正完成之前终止它，注意力滑向了*已完成*。按顺序防御：首先精炼完成标准（廉价、局部）；只有当它不可缩减地模糊*且*你观察到了冲动时，才通过拆分隐藏后置步骤（序列切口）。
- **重复 (Duplication)** — 同一个含义存在于不止一个地方。付出维护和 token 成本，并夸大了含义在梯子上的显眼程度，超出其真实层级。
- **沉积 (Sediment)** — 因为添加感觉安全而删除感觉危险所沉淀的过时层。任何没有剪枝规范的 Skill 的默认宿命。
- **膨胀失控 (Sprawl)** — Skill 过于冗长，即使每一行都是有效且唯一的。损害易读性和可维护性并浪费 token。解药是梯子：在指针背后公开暴露**参考**，并按**分支**或序列拆分，使每条路径仅承载其所需的内容。
- **无操作 (No-op)** — 模型默认已经在遵循的行，因此你付出了负载去说废话。测试标准：与默认情况相比它是否改变了行为？微弱的主导词（当代理已经挺彻底时写 _be thorough_）是无操作；修复方案是用一个通过测试的更强词汇（_relentless_），而不是换用不同的技巧。
- **否定句引导 (Negation)** — 通过禁止进行操纵会适得其反：_不要去想粉色大象_ 命名的了大象并使其更容易被触发，而不是更不易。提示**肯定/正面预期** — 声明目标行为，以便禁止的行为永远不被提及；只有作为你无法以肯定句表达的硬性安全护栏时才保留禁令，即便如此也要将其与替代操作配对。
