# 词汇表 — 编写优秀 Skill (Building Great Skills)

构建优秀 Skill 的领域模型。Skill 的存在是为了从随机/概率系统 (stochastic system) 中梳理出确定性 (determinism)；核心美德是**可预测性 (Predictability)**，下文中的每个术语都是作用于它的杠杆。这是 [`writing-great-skills`](SKILL.md) 的公开参考文档。

这些术语按维度分组：**调用 (Invocation)**（如何触达 Skill）、**信息层级 (Information Hierarchy)**（其内容如何编排）、**引导/操纵 (Steering)**（如何塑造代理的运行时行为）以及**剪枝/修剪 (Pruning)**（如何保持其精炼）。每种**失败模式 (failure mode)** 都跟在其解决的杠杆旁，并标记为 _failure mode_。

定义中任何**加粗的术语**本身均在本词汇表中定义；可通过对应标题查找它们。

## 可预测性 (Predictability)

Skill 使代理在每次运行中以相同的*方式*表现的程度 — 相同的流程，而不是相同的输出（一个头脑风暴 Skill 应该*可预测地*发散；它的 token 变化，它的行为不变化）。每个其他术语服务的核心美德 — 成本和可维护性是它的症状，而不是对手。

_应避免使用_：一致性 (consistency)、可靠性 (reliability)、健壮性 (robustness)、输出确定性 (output-determinism)

## 调用 (Invocation)

如何触达一个 Skill — 以及为该选择付出的两种负载成本。

### 模型调用 (Model-Invoked)

保留其 **description** 字段的 Skill，以便代理可以看到并自主触发它 — 且人类仍然可以输入其名称，因此模型调用始终*包含*用户触达。不存在仅限模型的独立状态：描述始终只*增加*代理的发现能力，绝不会移除人类的触达能力。代价是每轮对话都需付出永久的**上下文负载 (context load)**，以换取可发现性。可被其他 Skill 触达，因为使其可被代理发现的描述也使其可被调用。内容全为**参考 (reference)** 的模型调用 Skill 也是共享参考的一个归宿：另一个 Skill 可以调用它，因此多个 Skill 所需的参考可以集中存在于一个地方。仅在代理必须自行触达该 Skill 时才选择模型调用；如果它除了手动之外从不触发，请删除描述且不付出上下文负载。

_应避免使用_：能力 (ability)、工具 (tool)、功能 (capability)

### 用户调用 (User-Invoked)

去掉了 **description** 的 Skill — 对代理不可见，只有人类输入其名称才能触达（仅限用户，而 **模型调用** 是用户与代理兼有）。它牺牲了代理的可发现性，换取零**上下文负载 (context load)**。因为它没有描述，除了人类之外没有任何事物能够触达它：没有任何其他 Skill 可以触发它。

_应避免使用_：过程 (procedure)、工作流 (workflow)、命令 (command)

### 描述 (Description)

Skill 的机器可读触发器，也是**模型调用** Skill 被迫始终保持加载的唯一**上下文指针 (context pointer)**。它的存在本身*就是*调用维度的界限：保留它，Skill 就是模型调用的（且可被其他 Skill 触达）；删除它，Skill 就是**用户调用**的，仅可由人类触达。模型调用 Skill 的**上下文负载**的来源。

_应避免使用_：frontmatter、摘要 (summary)

### 上下文指针 (Context Pointer)

代理上下文中所保持的引用，命名了某些上下文之外的材料并编码了触达它的条件。**description** 是顶层上下文指针（上下文窗口 → Skill）；指向公开文件的指针是下一级的同类对象。它的措辞（而不是目标本身）决定了代理*何时*触达 — 以及*多可靠地*触达。位于措辞软弱的指针背后的必备目标是一个变异 Bug (variance bug)：首先精炼措辞，只有在精炼失败时才将材料内联。

_应避免使用_：链接 (link)、引用 (reference)、导入 (import)

### 上下文负载 (Context Load)

**模型调用** Skill 施加给代理上下文窗口的成本 — 它的 **description** 始终加载，既消耗 token 又消耗注意力。这是**用户调用** Skill 通过没有描述所规避的成本，也是限制拆分为更多模型调用 Skill 的阻尼器。

_应避免使用_：token 成本 (token cost)、上下文膨胀 (context bloat)

### 认知负载 (Cognitive Load)

**用户调用** Skill 施加给人类的成本 — 他们必须在大脑中保留的内容：存在哪些 Skill 以及何时触达每一个（人类是索引器）。这是**模型调用**通过具备代理可发现性所消除的成本，也是限制拆分为更多用户调用 Skill 的阻尼器。这不是要最小化的成本：它是人类主观能动性的代价，也是某些 Skill 保持用户调用的原因。在人类判断力至关重要的地方付出它；在不需要的地方消除它。

_应避免使用_：人类索引 (human index)、负担 (burden)、开销 (overhead)

### 路由 Skill (Router Skill)

一种**用户调用**的 Skill，其工作是指向你的其他用户调用的 Skill — 命名每一个以及何时触达它 — 这样人类只需要记住一个 Skill 而不是许多个。它只能提示，绝不能触发它们：用户调用的 Skill 没有 **description**，因此除了人类之外没有任何事物能够触达它们。当用户调用的 Skill 激增时解决**认知负载**的良方。

_应避免使用_：分发器 (dispatcher)、菜单 (menu)、注册表 (registry)、索引 (index)、路由过程 (router procedure)

### 粒度 (Granularity)

你划分 Skill 的精细程度。更精细的划分会消耗两种负载之一：更多**模型调用**的 Skill 会消耗**上下文负载**（更多描述拥挤在窗口中并争夺注意力）；更多**用户调用**的 Skill 会消耗**认知负载**（人类需要记住和触达的内容更多）。两条切口指导划分：按**调用**维度，当你有一个明确的**主导词**来触发它时，拆分出一个模型调用的 Skill — 一个你在提示词中实际使用的触发词；按**序列**维度，当一个步骤的**后置步骤**需要隐藏时拆分一系列**步骤**，因为将其隔离在自己的上下文中可以清空后续内容。谨防反向操作：合并序列会将每个步骤的后置步骤暴露给后续步骤，诱发提前完成。

_应避免使用_：分块 (chunking)、模块化 (modularity)

## 信息层级 (Information Hierarchy)

Skill 内容的编排方式，以及每个片段在梯子上下沉的位置。

### 信息层级 (Information Hierarchy)

按代理需要材料的紧迫程度排名的 Skill 内容 — 由两条切口产生的单个梯子。梯子横木：

- **步骤 (Steps)** — 文件内，主层级
- **参考 (Reference)**，文件内 — 次层级
- **参考 (Reference)**，公开暴露 — 位于**上下文指针**背后

没有**步骤**的 Skill 仅使用底部两横木 — 通常是合法平铺的同级集合（例如审查的每条规则都在一个横木上），这是一个良好的编排，而不是坏味道。层级独立于调用：无论 Skill 是全步骤、全参考还是两者兼有，它都可以是模型或用户调用的。当 Skill 拥有步骤时，本应公开暴露的文件内参考会掩埋它们，并将关注它们变成掷硬币 — 这是一个变异杠杆，而不仅仅是易读性杠杆。保持梯子顶部清晰易读；将能够下沉的内容向下推。

_应避免使用_：结构 (structure)、组织 (organization)、布局 (layout)

### 步骤 (Steps)

代理执行的有序动作 — 当 Skill 拥有它们时，是其内容的主层级，也是在 SKILL.md 中争得一席之地的地方。并非每个 Skill 都拥有步骤：Skill 可以是全步骤 (`tdd`)、全**参考**（审查）或两者兼有，与调用无关。每个步骤都终止于一个**完成标准**，无论是清晰的还是模糊的。

_应避免使用_：工作流 (workflow)、说明 (instructions)、编排 (choreography)

### 参考 (Reference)

代理按需查阅的材料 — 定义、事实、参数、示例、条件说明。当 Skill 拥有**步骤**时，它是次要的；当 Skill 没有步骤时，它是全部内容；或者它完全存在于任何 Skill 之外 — 参见 **外部参考**。通过**上下文指针**触达，也是**渐进式暴露**的主要候选对象。

_应避免使用_：支持材料 (supporting material)、文档 (docs)、背景 (background)

### 外部参考 (External Reference)

存在于 Skill 系统之外的**参考** — 纯文件、无 **description**、无 **steps**、不可调用 — 任何 Skill 都可以指向它。无需自行触发的共享参考的归宿，也是两个**用户调用**的 Skill 唯一可以使用的共享归宿，因为两者都没有描述，因此都不能触发对方。

_应避免使用_：文档 (doc)、资源 (resource)、知识库 (knowledge base)

### 渐进式暴露 (Progressive Disclosure)

将**参考**在梯子上向下移动 — 移出 SKILL.md 并置于**上下文指针**背后 — 以保持顶部清晰易读。主要不是 token 优化；这是保护**信息层级**的方式。由**分支**授权：暴露仅某些分支需要的材料，内联每条路径都需要的内容，如果指针在必备材料上触发不可靠，精炼其措辞，仅在精炼失败时拉回内联。

_应避免使用_：惰性加载 (lazy loading)、分块 (chunking)

### 同置归集 (Co-location)

将代理一次性所需的材料保持在一个地方 — 某个概念的定义、规则和注意事项集中在一个标题下，而不是散落在文件中 — 这样阅读一部分就会连带阅读其相邻内容。文件内对**信息层级**的补充：层级决定了片段*下沉多深*；同置归集决定了到达该处后*什么放在其旁边*。对于一大块**参考**的正确格式没有固定的公式；测试标准是 Skill 应该读起来像为代理编写的文档，而集中归集的材料读起来是那样，散落的材料则不是。不同于**重复**：重复是在两个地方重述同一个含义，而散落是将单个含义碎片化到多处。

_应避免使用_：分组 (grouping)、聚类 (clustering)、内聚 (cohesion)

### 膨胀失控 (Sprawl)

_失败模式 (failure mode)。_ Skill 过于冗长 — SKILL.md 中的行数过多 — 无论它们是过时的还是重复的。即使是全有效、全唯一的 Skill 也可能会膨胀失控。它消耗易读性（代理在采取行动之前要浏览更多内容，注意力在冗余中被稀释）、可维护性（每多一行都是需要保持**相关性**的一行）和 token。解药是**信息层级**：将**参考**推到**上下文指针**背后，并按**分支**或序列进行拆分，使每条路径仅承载其所需的内容。不同于**沉积 (sediment)**（来自过时累积的长度）和**重复 (duplication)**（来自重复含义的长度） — 膨胀失控就是长度本身，无论其原因如何。

_应避免使用_：膨胀 (bloat)、长度 (length)、体积 (size)、冗长 (verbosity)

## 操纵与引导 (Steering)

将代理运行时行为塑造为面向**可预测性**的杠杆。

### 分支 (Branch)

可以调用 Skill 的不同方式 — Skill 处理的某种情况 — 从而不同的运行在其中采取不同的路径。拥有许多步骤的 Skill 可能承载许多分支；线性 Skill 则没有。

_应避免使用_：路径 (path)、情况 (case)、分叉 (fork)

### 主导词 (Leading Word)

一个精炼的概念 — 也被称为 *Leitwort*（引导词） — 已经存在于模型的预训练中，代理在运行 Skill 时用它来进行思考。它通过调用模型已经持有的先验知识，用尽可能少的 token 编码了一个行为原则（例如 _lesson_、_proximal zone of development_、_fog of war_、_tracer bullets_）。作为一个 token 重复，而不是作为句子重复，它在整个 Skill 中累积了一个分布式定义，并锚定了整块行为区域。如果你定义清晰，自己造词也是可行的，但造出来的词无法调动先验知识 — 你在定义 token 上付出的代价，正是预训练词汇免费赠予的。优先选择现有的词汇。

主导词两次服务于**可预测性**。在正文中，它锚定了**执行** — 每次出现该概念时代理都会采取相同的行为，在平铺的参考内部，它将注意力集中在要查找的一类事物上，在每次运行中招募正确的检查。在 **description** 中，它锚定了**调用** — 不仅仅是在 Skill 内部：当同一个词保存在你的提示词、文档和代码库中时，代理会将该共享语言连接到 Skill 并更可靠地触发它。用你在希望使用 Skill 时实际使用的主导词来撰写描述。

_应避免使用_：关键字 (keyword)、术语 (term)、母题 (motif)

### 完成标准 (Completion Criterion)

告知代理某项单元工作已完成的条件 — 代理用来进行评估的目标。两个属性使其成为杠杆，而不仅仅是质量属性。它的**清晰度**（代理能否区分完成与未完成？）能抵抗**提前完成** — 模糊的界限（“达成理解”）会让代理误判已完成并滑向下一步；此维度需要*步骤*来发挥作用，因为提前完成是步骤之间的失败。它的**要求程度**（它需要多少内容）设定了**底层调查工作量 (legwork)** — “核对每个修改过的模型”会强制进行彻底的工作，而“生成一个变更列表”则不会 — 且此维度*不*受步骤限制：它也可以约束平铺参考的主体，这就是没有步骤的 Skill 依然承载完备性门槛的原因（“应用每条规则”）。最强的标准既是可检查的，也是完备的。

_应避免使用_：完成条件 (done condition)、退出条件 (exit condition)、停止规则 (stopping rule)

### 底层调查工作量 (Legwork)

代理在单个步骤内部在幕后所做的工作 — 读取文件、探索代码库、做出修改、挖掘所需内容，而不是推卸给用户。它存在于步骤结构之下：绝不写成独立的步骤，隐喻在措辞中，由代理掌控而不是由 Skill 掌控。它是**后置步骤**在跨步骤拉动上的步骤内对应物。由**主导词**（_comprehensive_、_thorough_）或要求工作完备的**完成标准**提升 — 包含应用于平铺参考的要求维度，这正是驱动平铺参考 Skill 覆盖其所有横木的动力。当该要求缺失或**提前完成**切短步骤时，工作量就会变薄。

_应避免使用_：范围 (scope)、努力 (effort)、勤勉 (diligence)、覆盖率 (coverage)

### 后置步骤 (Post-Completion Steps)

跟随当前步骤之后的**步骤**。如果可见，它们会将代理拉向前方的**提前完成** — 看到的越多，牵引力越强；防御手段是通过将步骤序列拆分为两个来隐藏它们。

_应避免使用_：视野 (horizon)、战争迷雾 (fog of war)、前瞻 (lookahead)

### 提前完成 (Premature Completion)

_失败模式 (failure mode)。_ 在当前步骤真正完成之前就终止它，因为代理的注意力滑向了“已完成”而不是工作本身。步骤之间的失败：它需要**步骤**才会发生 — 一个没有步骤却提前退出的 Skill 不是提前完成，而是未达要求的薄弱**底层调查工作量**。两股力量之间的拉锯战：可见的**后置步骤**（向前的拉力）与**完成标准**的清晰度（阻力 — 尖锐、可检查的门禁能守住；模糊的门禁会妥协）。模糊性是必要条件：尖锐的界限无论多少后续步骤可见都能抵御拉力，因此一个从不轻举妄动步骤不需要防御。两个杠杆可以守住出现轻举妄动的步骤，但需按顺序使用：**首先精炼界限** — 它是局部且廉价的。只有当标准不可缩减地模糊*且*你实际观察到了冲动时，才**隐藏后续步骤** — 且隐藏只有在跨越真正的上下文边界时才有效（用户调用的手动交接或子代理派发；内联的模型调用会在上下文中留下后续步骤，无法清空任何内容）。这是导致底层调查工作量变薄的原因之一，但与之不同：即使一个步骤完整运行到结束，工作量依然可能变薄。

_应避免使用_：过早闭合 (premature closure)、冲动 (the rush)、急躁 (rushing)、走捷径 (shortcutting)

### 否定句引导 (Negation)

_失败模式 (failure mode)。_ 通过禁止性指令进行操纵 — 告知代理*不要*做什么 — 这会将禁止的行为拉入上下文，使其*更容易*被触发，而不是更不易被触发。“不要去想粉色大象”，大象就占据了全部；“绝不编写冗长的注释”，冗长就是代理刚刚读取的模式。否定词是一个微弱的修饰语，被强激活的概念所冲刷，因此禁止声明在某种程度上被半理解为执行该事项的指令。它的**主导词**就是*大象*：即禁令在框架中命名的任何事物。解药：提示**肯定/正面预期** — 描述目标行为（“编写单行注释”），以便禁止的行为永远不被提及。只有作为你无法以肯定句表达的硬性安全护栏时，禁令才争得一席之地；即便如此，也要将其与正面目标配对，以便注意力落脚在要做的事情上。

_应避免使用_：反弹效应 (ironic rebound)、否定提示 (don't-prompting)、粉色大象 (the pink elephant)

## 剪枝与修剪 (Pruning)

保持 Skill 的精炼 — 每种补救措施都与其解决的失败相配对。

### 单一事实来源 (Single Source of Truth)

期望的状态：每个含义保存在恰好一个权威位置，因此对 Skill 行为的修改就是在一处进行修改。**重复**是对它的破坏。

_应避免使用_：归宿 (home)、规范位置 (canonical location)

### 重复 (Duplication)

_失败模式 (failure mode)。_ 同一个含义被赋予了不止一个**单一事实来源**。它付出维护成本（修改了一处，你必须修改其他地方）、付出 token 成本，并夸大了显眼程度 — 重复一个含义会使其在梯子上的权重超出其真实层级。与**主导词**偶然相反，主导词是通过重复一个 token（绝不是重述含义）来有针对性地提高注意力。

_应避免使用_：重复 (repetition)、冗余 (redundancy)

### 相关性 (Relevance)

某一行是否依然与 Skill 所做的事相关 — 用于决定保留什么的视角。一行丢失相关性要么是因为从不与任务相关（单纯的阐述，或者应该公开暴露的**分支**），要么是因为过时：随着其描述的行为或世界发生变化而脱离实际。更短的 Skill 更容易保持相关性，因为每一行检查起来更廉价。不同于 **无操作 (no-op)**：相关性问的是某一行是否与任务相关，而不是问它是否改变了行为。

_应避免使用_：承重 (load-bearing)、陈旧性 (staleness)、新鲜度 (freshness)

### 沉积 (Sediment)

_失败模式 (failure mode)。_ 沉淀在 Skill 中且从不被清理的旧内容层，因为添加感觉安全而删除感觉危险 — 因此过时和不相关的行不断累积，你必须深入向下挖掘才能找到依然生效的内容。任何缺乏剪枝规范的 Skill 的默认宿命；**相关性**的缓慢侵蚀，与**重复**的重述含义不同。

_应避免使用_：堆积 (accretion)、膨胀 (bloat)、废料 (cruft)、腐烂 (rot)

### 无操作 (No-Op)

_失败模式 (failure mode)。_ 一条没有改变任何事情的指令，因为模型默认已经在这样做了 — 你付出了负载去告诉代理它反正会做的事。测试标准：与默认情况相比，某一行是否改变了行为？一行可以完全具备**相关性**但依然是无操作。使**主导词**免费的相同先验知识使无操作变得毫无价值。

主导词是一种*技巧*；无操作是对某一行内容的*裁决* — 它们相交。一个过于微弱无法战胜默认情况的主导词就是无操作（当代理已经挺彻底时写 _be thorough_），修复方案是用一个通过裁决的更强词汇（_relentless_），而不是换用不同的技巧。因此，无操作测试 — 与默认情况相比是否改变了行为？ — 也是你评估主导词是否赚回其重复成本的方式。这是相对于模型而言的，而不是相对于读者而言的：两个人对某一行是否是无操作产生分歧，是对默认情况产生了分歧，应通过运行 Skill 来解决，而不是通过辩论。

_应避免使用_：冗余指令 (redundant instruction)、重述显而易见的事 (restating the obvious)、啰嗦 (belaboring)
