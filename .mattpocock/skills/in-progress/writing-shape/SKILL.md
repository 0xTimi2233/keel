<what-to-do>

用户已传递（或将要传递）一份原始素材的 Markdown 文件。将其视为输入素材堆 — 从整洁的碎片列表到大段未结构的散文再到逐字稿皆可。格式并不重要。在做任何其他事情之前，先从头到尾完整阅读它。

然后运行一个塑造环节，生成一份独立的文章文档。这是**挖掘阶段 (exploit)**：探索阶段已完成，素材堆已固定 — 选定一个结构，并挖掘素材堆来填充它。不要编辑原始素材文件 — 对本 Skill 而言它是只读的。

如果用户未说明将文章保存到何处，询问一次并记住该路径。

</what-to-do>

<supporting-info>

## 循环流程

1. **阅读素材堆。** 完整阅读输入文件。形成对其内容的整体感知。
2. **确立前提知识。** 与用户敲定读者在进入阅读时已知的内容 — 即从一开始就**已铺垫说明 (grounded)** 的概念。其他所有概念在后续区块能够使用之前，必须先由某个区块进行铺垫说明。参阅 [铺垫说明 (Grounding)](#铺垫说明-grounding)。
3. **起草 2–3 个备选开头。** 每个开头应该暗示文章的不同主点或立意角度。展示所有备选开头。强制用户选择或组合出一个混合开头。选定的开头决定了文章其余部分必须做什么。
4. **逐段扩建。** 开头确定后，询问“基于这个开头，读者接下来需要听到什么？”从素材堆中提取材料来回答。下一个区块只能依赖已铺垫说明的概念，并在落脚时铺垫说明新概念。讨论下一个区块采取的呈现形式 — 段落、列表、表格、呼应块 (callout)、引用或代码块。每一种格式选择都应该是深思熟虑且站得住脚的。
5. **边讨论边追加到文章文件。** 不要打包批量写入。立即写入每个达成一致的段落或区块，以便用户可以看到文章成型。
6. **循环步骤 4，直到文章完成。** 由用户决定何时完成。

## 铺垫说明 (Grounding)

每一个**概念 (concept)** 必须在区块能依赖它之前被**铺垫说明 (grounded)**：读者要么在进入阅读时就已经了解，要么在前面的区块中遇到过。依赖尚未铺垫说明的概念的区块会让读者掉队。单位是概念，而不是具体的词汇：即使眼前没有专业术语，区块也可能依赖读者缺乏的某种思想。当概念拥有名称 — 即**术语 (term)** 时，铺垫说明它意味着将思想与术语一同落地呈现。

概念通过以下两种方式之一获得铺垫说明：

- **前提条件 (Prerequisite)** — 在开头之前已铺垫说明。读者自带此认知。在开头处固定。
- **引入 (Introduced)** — 由某个区块确立，从那时起对文章的其余部分均已铺垫说明。

保持一份已铺垫说明内容的清单。当你询问“读者接下来需要听到什么？”时，下一步所需的未铺垫说明概念本身就是答案：先在此处或先前的区块中铺垫说明它 — 否则你无法推进下一步。这是在更高层面上对 [从素材堆中挖掘](#从素材堆中挖掘) 的差距命名：那里是素材堆缺少材料；这里是文章缺少基石。

核心杠杆在于你将什么设定为前提条件，以及在文章内部铺垫说明什么。 upfront 门槛要求过高，你会关上读者的大门；内部铺垫说明过多，开头又会沉溺于概念定义中。在确立前提条件时与用户敲定这一点。

## 对话感觉

这是一个反转的盘问环节。在构思阶段，问题是“你实际上看到了什么？”在这里，问题是“这篇文章实际上在论证什么，读者需要按什么顺序听到它？”敢于推翻弱项。拒绝让软弱的过渡滑过去。如果一个段落没有争取到属于它的位置，剪掉它。

持续使用的具体招式：

- “这个段落为读者做了哪些前一段落没有做的事？”
- “如果我删掉这一段，什么会脱节？”
- “这是用散文还是应该用列表？为什么用散文？”
- “这句话在承担两项工作 — 拆开它或二选一。”
- “开头承诺了 X。我们已经偏向了 Y。要么重新串联，要么修改开头。”

## 从素材堆中挖掘

将原始素材视为矿石采掘场，而不是剧本。提取一个碎片，重新加工以契合上下文段落，然后放置它。一个碎片可以被拆分到多个段落中、与另一个碎片合并，或进行改述。素材堆的工作是被采掘；文章的工作是以统一的声音呈现。

如果素材堆缺乏文章所需的内容，明确指出缺口：“我们在这里需要一个示例，而素材堆里没有 — 现在给我一个，或者我们删掉这个章节。”

## 需要真正开展辩论的格式选择

在选择如何呈现一个区块时，与用户大声权衡这些取舍，而不是在内心默想：

- **散文 vs 列表。** 散文承载论证；列表承载并行项。如果各项并非真正并行，散文更好。如果是，列表更易于快速扫视。
- **正文内联 vs 呼应块 (callout)。** 技巧、警告和旁白使用呼应块 (`> [!TIP]`, `> [!NOTE]`) — 但前提是它们放在正文内联中会真正干扰主线论证。否则保持正文内联。
- **表格 vs 重复结构。** 如果相同的形态使用相同的字段重复出现 3 次以上，使用表格。否则使用带加粗前导词的散文。
- **引用 vs 改述。** 当原句措辞本身就是要点时引用。当仅思想重要时改述。
- **代码块 vs 内联代码。** 多行、可运行或具有说明性的 → 代码块。单个 token 或标识符 → 内联代码。

## 写作节奏

当每个区块达成一致时追加到文章文件中。在每次写入之前重新从磁盘读取文件 — 用户可能在轮次之间进行了编辑。切勿盲目覆盖。如果用户希望重写某个段落，在原地编辑该特定段落；不要动其他部分。

## 超出范围

- 挖掘素材堆中不存在的新碎片（按照“从素材堆中挖掘”处理缺口）。
- 编辑原始素材文件。
- 发布、针对特定平台排版或添加用户未要求的 frontmatter。
