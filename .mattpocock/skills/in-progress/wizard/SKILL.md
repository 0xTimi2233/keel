# 导引助手 (Wizard)

一个 **导引助手 (wizard)** 是一段 bash 脚本，引导人类一步一步地完成手动流程 — 这些流程手动操作起来繁琐且每次向 AI 重新解释也很繁琐。它会打开每个 URL，明确告知点击和复制什么，捕获数值，写入其所属的位置（`.env`、GitHub secrets），在每个阶段进行确认，并显示剩余时间。它可能会配置第三方服务、运行一次性迁移或将项目从一个状态推进到另一个状态。

令人愉悦的 UX 已经在 [template.sh](template.sh) 中得到解决 — 显示带剩余时间的进度、确认门禁、跨平台 URL 打开（包含 WSL）、隐藏敏感信息输入、幂等的 `.env` 插入更新 (upserts)、`gh secret`/`gh variable` 写入，以及结尾的总结。**你的工作仅在于确定流程范围并撰写其阶段。** 在 `STAGES` 标记之上的函数库在每个 wizard 中都是完全相同的；这种一致性正是要点所在 — 绝不要手动编辑它。

默认情况下，wizard 是即用即弃的 (ephemeral) — 为一次运行而构建，保存到临时路径或 `scripts/` 路径，任务完成后予以删除。仅当用户需要将可复用的初始化设置路径留在仓库中时才进行 commit。

## 流程

### 1. 确定流程范围

梳理人类必须采取的每一个手动步骤以及沿途捕获的每一个数值。首先读取代码库 — 不要冷不丁询问：

- 对于初始化设置：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置以及 `.github/workflows/*`（每一个 `secrets.*` / `vars.*` 引用都是 wizard 必须产生的数值）。
- 对于迁移或状态转换：当前的初始状态、目标状态以及它们之间不可逆的操作。

然后向用户展示按顺序排列的阶段列表以及每个阶段产生的数值，并予以确认 — 他们可能会添加、丢弃或重新排序。

**完成标准：** 每个阶段都按顺序命名，并且对于每个捕获的数值你都知道 (a) 人类从哪里获取它，(b) 它写入哪里（`.env`、GitHub secret、两者兼有，或者无 — 有些阶段是纯操作），以及 (c) 它是否是敏感信息（隐藏输入）或公开信息。

### 2. 映射每个阶段的旅程

对于每个阶段，编写人类遵循的精准路径：打开哪个 URL、在那里做什么、在什么位置显示数值、它填充哪个变量 — 例如“Dashboard → Developers → API keys → Reveal test key → copy”。如果你实际上不知道当前的 UI 或准确的命令，请诚实说明并询问用户或检查文档 — 切勿捏造可能不存在的步骤。

**完成标准：** 每个阶段都能追溯到陌生人可以遵循的具体指令。

### 3. 编写导引脚本

将 `template.sh` 复制到目标路径。按照依赖顺序，用每个步骤对应的 `stage` 替换示例阶段。使用库中的辅助函数 — `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm` — 并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估计值（这决定了剩余时间的显示）。

保持模板设定的高标准：在询问数值之前先打开 URL，对任何敏感信息使用 `ask_secret`，对每一个持久化数值使用 `write_env`，仅对 CI 真正需要的数值使用 `set_secret`，并在任何不可逆操作之前使用 `confirm`。每个 `stage` 都会清空屏幕，以便仅当前步骤可见 — 将一个阶段保持为一项专注的任务，避免人类所需的内容滚动消失。不要修改标记之上的函数库。

### 4. 验证并交接

- 运行 `bash -n <script>`；如果可用则运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行该脚本 — 它会打开浏览器并等待人类输入。改用静态推演：验证步骤 1 中的每一个数值都被捕获并落到了步骤 1 所说的位置，且每一个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告知用户如何运行它。如果这是一个可复用的初始化设置路径，进行 commit 并从 README 建立链接，以便下一个人可以直接运行脚本而不用询问 AI。
