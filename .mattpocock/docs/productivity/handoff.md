## 它的作用

`handoff` 将当前对话压缩归纳为一份**交接文档**（handoff document）——一份全新的 AI 代理可以阅读并在你停下的地方无缝接手工作的简短撰文。

它**不会**重复陈述在其他地方已经存在的内容。在规范文档、计划、ADR、issue、提交或 diff 中捕获的任何内容都通过路径或 URL 引用，绝不进行复制粘贴。该文档仅承载活跃的主线（live thread）——你刚才在做什么、为什么做以及接下来做什么——并保存到操作系统的临时目录中，而不是工作区中，因此它永远不会成为另一个需要额外维护的文档产物。

## 何时使用它

你可以通过输入 `/handoff` 来调用它——AI 代理不会自行主动触发它。附上一条关于下一会话要干什么的说明，文档就会针对该需求进行定制。

当对话已经足够长以至于其上下文面临风险时使用它——例如接近上下文上限、结束一天的工作，或者故意将工作转交给另一个代理——并且你希望在不携带整个对话记录的情况下保留主线。

## 文档包含的内容

- **活跃主线** —— 用对话本身的术语说明正在进行的事项及原因，扣除已经在其他地方记录的所有内容。
- **推荐技能** —— 下一个代理接手继续推进时应使用的技能指针。
- **引用而非复制** —— 指向保存了具体确定细节的 spec、计划、ADR、issue 和 diff 的链接和路径。
- **敏感数据脱敏** —— 在写入文档前对 API 密钥、密码和个人身份信息（PII）进行脱敏处理。

核心要点在于**压缩**（compaction）：交接就是将对话压缩至仅保留其可恢复的核心，从而让新的代理继承势头，而非杂音。

## 它的位置

`handoff` 是一个可随时使用的独立技能——它位于两个会话之间的接缝处，而不是处于构建链内部。它能够与它所指向其产物的那些技能天然配合：例如 [to-spec](https://aihero.dev/skills-to-spec)，因为一份已完成的 spec 恰好是交接文档予以引用而非重复表达的确定细节。当你不确定当下适合使用哪个技能时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你导航。
