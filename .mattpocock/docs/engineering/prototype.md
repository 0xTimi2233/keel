## 它的作用

`prototype` 用于构建一个小型、可抛弃的程序，其唯一任务就是解答一个设计疑问——这种状态模型感觉对不对，或者这个 UI 界面应该长成什么样。

该代码**从第一天起就是一次性/抛弃型的**，并作了相应标记。它不包含测试，除了维持其运行所需的错误处理之外没有其他错误处理，没有抽象，也没有持久化。重点在于快速学到经验然后将其删除——因此，一旦你开始对其进行加固（hardening），你就停止了原型设计。

## 何时使用它

你可以输入 `/prototype`，或者当任务匹配时 AI 代理会自动调用它。

当你在纸面上难以解决某个设计疑问时使用它：比如无法在脑海中穷尽所有情况的状态机，或者只有并排看到多个版本才能想象出来的界面。相反，如果是已构建的内容表现异常且你需要找出原因，请使用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；原型设计探索的是“构建什么”，而不是“已构建的东西为何损坏”。

## 两种分支路线

问题决定了原型的形态，主要有两种形态：

- **“这种逻辑 / 状态模型感觉对吗？”** —— 一个微型的交互式终端应用，用于推动状态机走过各种棘手情况，并在每次操作后打印完整状态，以便你可以观察发生了什么变化。
- **“这应该长成什么样？”** —— 在同一个路由/页面上展示几种截然不同的 UI 变体，可通过悬浮控制栏进行切换，从而让你对比真实的渲染效果而非凭空想象。

选错分支路线会浪费整个原型，因此问题优先级最高。两种分支路线都将状态保存在内存中，通过单个命令运行，并在每一步显示完整状态。

## 将原型作为第一手资料保存

一个完成的原型会留下两样东西。**答案**——结论加上它所解决的问题——是你持久捕获的内容（提交信息、ADR 或 issue）。**原型本身则是第一手资料**——结论所依托的可运行证据。

原型不属于主分支：没有测试，没有错误处理，没有需要维护的东西。但这并不是摧毁它的理由。一旦捕获了答案，请将任何经过验证的决策整合到真实代码中，然后在一个抛弃型分支上捕获该原型——独立于主分支、绝不合并——并在实现 issue 上留下指向它的上下文指针。主分支保持干净；对于任何想要重新运行该原型的其他人来说，原始探索距离他们只有一步之遥。留在主分支中烂掉的原型超出了其使命——而在侧枝上作为第一手资料保存的原型则恰如其分。

## 它的位置

`prototype` 是一个可随时使用的独立技能：你进入其中以解决设计疑问，然后退出。它的答案通常会输送给下一步——经过验证的状态模型或 UI 方向成为 [to-spec](https://aihero.dev/skills-to-spec) 撰写规范的确定输入，或者成为值得通过 [domain-modeling](https://aihero.dev/skills-domain-modeling) 记录的架构决策。当你不确定使用哪个技能或流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你导航。
