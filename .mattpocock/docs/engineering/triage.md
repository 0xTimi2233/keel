## 它的作用

`triage` 推动你项目跟踪器上的 Issue 通过一个由分流角色构成的微型**状态机**——对其进行分类、验证诉求、在需要时追问盘问使其成型，并留下一份供代理执行的简报（ready-for-agent brief）。

它绝不盲目打标签。每个经过分流的条目恰好携带一个**类别**角色（`bug` / `enhancement`）和一个**状态**角色（`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`），并且它采取*提出建议并等待*的原则——它向你说明其类别与状态裁定及背后的理由，然后仅根据你的指令执行操作。在任何内容被晋升为 `ready-for-agent` 之前，它会首先验证其真实性：Bug 必须被复现，PR 必须被检出并运行验证。

## 何时使用它

你可以通过输入 `/triage` 并用自然语言描述你的需求来调用它——AI 代理不会自行主动触发它。例如：“显示任何需要我关注的内容”、“让我们看看 #42”、“将 #42 移动到 ready-for-agent”。

当你的 Issue 跟踪器中堆积了原始的、未经评估的报告，且你希望对其进行归类、验证，并转化为 AI 代理或人类可以领取的任务时，就可以使用它。如果要把一次确定的对话转化为一份全新的 spec 规范文档，请使用 [to-spec](https://aihero.dev/skills-to-spec)；要将现有的 spec 拆分为 ticket，请使用 [to-tickets](https://aihero.dev/skills-to-tickets)。`triage` 的方向相反——它处理的是*已经*落入跟踪器中的内容。

## 前置条件

`triage` 需要读取和写入你的 Issue 跟踪器，因此 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 必须首先为该仓库配置好跟踪器和标签映射。上述角色名称是**规范定义**（canonical）——在你的跟踪器中的实际标签字符串可能有所不同，而配置正是用来提供该映射的。配置还决定了外部 PR 是否算作请求来源，以及谁算作外部人员。

## PR 是附带代码的 Issue

当跟踪器将外部 Pull Request 视为请求来源时，`triage` 会通过*完全相同*的状态机对其进行处理：相同的类别角色、状态角色和状态转换——只不过状态是对照 diff 差异而非单纯的文字报告来进行判定的。`ready-for-agent` 意味着附带了简报，AI 代理应该接手进行下一步代码操作；`ready-for-human` 意味着它已经准备好可以合并。自动发现界面仅展示外部 PR，但显式命名的 PR 无论作者是谁都会被分流处理。

## 撰写简报前先验证

将 `triage` 与临时打标签区分开来的关键步骤是验证。它通过提交者的步骤复现 Bug，或者检出 PR 并运行测试，然后反馈结果：通过代码路径确认、复现失败，或者详细信息不足（这本身就是强烈的 `needs-info` 信号）。它还会运行两项代码库检查——**冗余性**（这是否已经被实现？若是则标为 `wontfix`）和**先前拒绝记录**（`.out-of-scope/` 是否已经明确拒绝过该需求？）。一次经过确认的验证能产出强有力得多的代理简报；而盲目猜测则不能。

## 正常工作的标志

- 它处理的每个条目最终都恰好包含一个类别角色和一个状态角色——绝非零个，也绝非两个冲突的状态。
- 它向你递交带有理由说明的建议并等待指令，而不是自行盲目重新打标签。
- Bug 在到达 `ready-for-agent` 之前已被复现，PR 在到达之前已被运行验证。
- 它在跟踪器上发布的每条评论都以 `> *This was generated by AI during triage.*`（*本内容由 AI 在分流过程中自动生成。*）免责声明开头。

## 它的位置

`triage` 是对 Issue 跟踪器进行的**定期维护** pass——每当报告堆积时运行它，以保持队列井然有序且 `ready-for-agent` 栏目真实可靠。它位于跟踪器的最前沿，处于构建链的上游：它撰写的简报正是 [tdd](https://aihero.dev/skills-tdd) 稍后接手以实现的内容。当某个请求需要磨砺精炼时，它依赖 [grilling](https://aihero.dev/skills-grilling) 和 [domain-modeling](https://aihero.dev/skills-domain-modeling) 通过每次一个问题的方式将其盘问成型。它最近的邻居是 [to-spec](https://aihero.dev/skills-to-spec)，后者从全新对话中填充跟踪器，而 `triage` 则处理已存在的内容。当你不确定使用哪个技能或流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你导航。
