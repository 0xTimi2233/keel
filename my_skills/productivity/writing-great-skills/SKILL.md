Skill 的目标是可预测性：每次运行都执行同样的流程，而非追求完全相同的输出

默认模型已经很聪明，只写能改变行为的内容

## 文件结构

```text
my-skill/
├── SKILL.md            # 必需：元数据与核心指令
├── agents/openai.yaml  # OpenAI 扩展：UI 信息与调用策略
├── scripts/            # 可执行脚本
├── references/         # 按需读取的参考资料
└── assets/             # 输出时使用的模板与静态资源
```

按需创建可选目录，在 `agents/openai.yaml` 中只保留实际使用的 UI 字段和非默认配置

## 调用方式

- 模型需要主动发现 Skill 时使用模型调用，在 `description` 中写清作用和用户会使用的触发词
- 同一触发条件只保留一种说法，例如“编写 Skill”和“新建 Skill”选择更常见的一种
- Skill 只应由用户主动选择时使用用户调用，设置 `allow_implicit_invocation: false`，`description` 不写触发词
- 模型调用占用上下文，用户调用要靠用户记住 Skill；根据谁应该发现它来选择
- 需要用户记住的 Skill 多到难以选择时，建立路由 Skill，列出可用 Skill 与适用场景

## 编写正文

- Skill 可以由步骤、参考内容或两者共同组成
- 纯参考型 Skill 直接写规则
- 有步骤时先写步骤，再写每次执行都要用的规则
- 按依赖关系排列步骤，每一步都用可检查的完成条件收尾
- 需要完整覆盖时，在完成条件中明确“全部”“每个”等范围
- 把同一概念的定义、规则和例外放在一起

## 选择拆分方式

- 用户可以单独提出这项任务时，拆成新的 Skill
- 内容只是部分场景需要的知识时，放进 `references/`，并在 `SKILL.md` 中写明何时读取
- 操作会重复执行且结果需要稳定时，写进 `scripts/` 并实际运行验证
- 模板或静态资源会直接用于输出时，放进 `assets/`
- 后续步骤让当前步骤草草收尾时，先收紧完成条件；仍然草草收尾，再把后续步骤拆成单独流程

## 锚点词

强锚点是模型已经学过、能直接唤起一组行为的常用词

- 优先复用用户、文档和代码中的既有用词，让同一个词连接调用与执行
- 中英文谁更准确、更精炼就用谁
- 找不到准确锚点时直接说明目标行为
- 特殊含义只定义一次，后续只复用锚点

## 精简

- 每个含义只保留一个权威位置：`SSOT`
- 删除陈旧内容，检查每句话是否仍与 Skill 的当前作用相关
- 逐句执行 `no-op` 检验：临时删除一句，若预期行为不变，删除整句
- `description` 每轮都参与调用，删减标准应比正文更严格
- 内容膨胀时，按需加载或拆分

## 中文行文

- 以“通顺”为准：使用常用词，保持自然
- 使用主动句，拆开长定语，按中文语序重写，直到全文通读自然
- 默认省略主语；只有指代提出需求的人时才写“用户”
- 用正向目标规避白熊效应；必须写禁止句时，紧接替代行为
- 中文使用全角标点，以换行结束句子，省略句末句号；代码、路径、字段名和完整英文句式使用半角标点
- 按语义重写英文破折号，解释关系改用冒号
- 用正文和标题表达层级，字面量使用反引号，省略斜体和重复加粗

## 交付检查

- 逐句执行 `no-op` 检查、白熊效应检查和锚点词检查
- 确认脚本已运行、参考资料有读取时机、`assets/` 有使用位置
