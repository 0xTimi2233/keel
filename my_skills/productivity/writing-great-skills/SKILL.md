# 编写高质量 Skill

Skill 的根本目标是过程可预测性：约束每次运行采用同一方法，允许具体答案随任务变化

默认模型已具备通用知识与推理能力，只写能够改变其默认行为的内容

## 执行流程

### 一、界定行为增量

- 新建 Skill 时，从用户的真实请求和示例中提取目标行为、触发语义与失败边界
- 改写 Skill 时，通读原 Skill、附属资源和人类文档，先还原意图与执行顺序，再决定保留、合并、拆分或删除
- 对照模型的默认做法，写出加载 Skill 后必须出现的可观察变化

完成判据：能够说明加载前后的行为差异，每个主要场景有触发正例，容易混淆的边界有反例

### 二、设计调用

- 需要模型自行识别任务或被其他流程发现时，使用模型调用，并在 `agents/openai.yaml` 中设置 `allow_implicit_invocation: true`
- 只应由用户明确点名时，设置 `allow_implicit_invocation: false`
- 两种模式都保留 `name` 和 `description`，由 `policy` 控制是否隐式加载
- 在 `description` 开头写能力与主要锚点，再覆盖彼此独立的触发分支
- 每个分支只写一个触发语义，删除同义改写和正文身份说明

完成判据：调用策略符合预期，每个独立分支都由一条唯一触发语义覆盖

### 三、搭建信息层级

把内容放在能够保证执行质量的最晚加载位置：

1. `description`：只承担调用判断
2. `SKILL.md`：放置执行步骤和所有分支都需要的规则
3. `references/`：通过渐进披露承载仅特定分支需要的文档、变体和长示例

- 从 `SKILL.md` 直接链接每份参考资料，并在链接旁写明加载条件
- 用 `scripts/` 固化重复且需要确定性的操作，用 `assets/` 保存供产出复用的模板与素材
- 把同一概念的定义、规则与例外放在一起
- 遵守 `SSOT`：每个含义只保留一个权威定义

完成判据：核心步骤所需信息均随 `SKILL.md` 加载，每份外部资源都有明确且可靠的加载条件

### 四、编排步骤与拆分边界

- 按依赖关系排列步骤，使用省略主语的祈使句
- 每个步骤都以可检查的完成判据收尾，需要完整覆盖时使用穷尽条件
- 按任务脆弱度设置自由度：开放任务写原则，稳定模式写伪代码，易错操作固化为脚本
- 仅当一组行为拥有独立触发语义时，拆成新的模型调用 Skill
- 仅当某些内容只服务特定分支时，下沉到 `references/`
- 当前步骤发生过早收敛时，先收紧完成判据；若判据已达到可判定上限而后续步骤持续造成抢跑，再拆分执行序列

完成判据：每次拆分都由独立调用、条件加载或已观察到的过早收敛支撑

### 五、选择锚点词

锚点词是模型预训练中已有的高密度概念，用一个词唤起一组稳定行为

- 比较中英文候选词的概念密度，选择更准确、更精炼的一方
- 优先使用已有概念；锚点精度不足时直接描述行为
- 首次出现时界定特殊含义，后续仅复用锚点
- 用 `no-op` 检验锚点强度；只复述默认行为的弱锚点应删除或替换

例如：

- `don't think of an elephant` → 白熊效应
- 每处只有一个权威定义 → `SSOT`
- 删除后行为不变 → `no-op`

完成判据：每个锚点都能准确替代一组更长的行为描述，含义单一明确

### 六、精简

- 逐句执行 `no-op` 检验：临时删除一句，若预期行为不变，删除整句
- 删除与当前行为无关、已经失效或只为人类补充背景的内容
- 合并重复含义，只保留 `SSOT`
- 对长驻上下文的 `description` 采用更严格的删减标准
- 以行为密度衡量精简效果

完成判据：每个保留句都能说明其行为增量，每个含义都只有一个权威位置

### 七、正向表达与中文审校

- 用正向目标取代禁止描述，让注意力落在目标行为上
- 仅对必须阻断的硬边界使用禁止句，并紧接应采取的替代行为
- 中文改写以行为等价为准，主动重组句式、结构与示例
- 将被动句改为主动句，拆解长定语，用中文语序重写翻译腔，省略冗余人称
- 默认省略主语；仅在指代提出需求的人时使用“用户”
- 中文内容使用全角标点，代码、路径、字段名和完整英文句式使用半角标点
- 中文句子以换行标记边界，省略句末句号
- 按语义重写英文破折号；解释关系使用冒号
- 用正文或标题承载概念层级，字面量使用反引号，省略斜体与重复加粗

完成判据：每句话都符合中文母语开发者的书面表达，全文通读自然连贯

### 八、验证

- 运行结构校验，修复 frontmatter、命名和目录问题
- 核对 `agents/openai.yaml` 与 `SKILL.md` 一致，特别检查调用策略
- 用应触发、边界反例和漏触发风险三类请求测试 `description`
- 在多个真实任务中检查执行过程是否稳定，允许输出随任务变化
- 对难以凭判断确定的 `no-op` 做加载前后对照测试

完成判据：结构校验通过，调用边界符合预期，重复运行采用稳定过程
