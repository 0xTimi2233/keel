skill 的目标是可预测性：每次运行都执行同样的流程，而非追求完全相同的输出

默认模型已经很聪明，只需写能改变行为的内容

## 文件结构

```text
my-skill/
├── SKILL.md            # 必需：元数据与核心指令
├── agents/openai.yaml  # OpenAI 扩展：UI 信息与调用策略
├── scripts/            # 可执行脚本
├── references/         # 按需读取的参考资料
└── assets/             # 输出时使用的模板与静态资源
```

## 调用方式

- **模型调用**：agent 可自主触发。代价是上下文开销：description 常驻上下文窗口。写法：在 description 写清触发场景（“当用户想要或提到…时使用”）
- **用户调用**：description 对 agent 不可见，只能由用户输入名字触发，不占上下文。代价是认知负担：用户需自行记忆存在。写法：设 `allow_implicit_invocation: false`，description 改为面向用户的一行摘要

仅当 agent 需自主触发时做成模型调用，其余做成用户调用。用户需调用 skill 过多时，写一个 router skill 汇总入口

## 编写 description

只写职责与触发场景，它每轮常驻上下文，精简标准比正文更严苛

- 一个场景只写一个触发条件，同义需合并

## 内容分层

内容分为 **步骤**（按顺序执行的动作）、**参考**（按需查阅的定义、规则）和 **模板**（占位填充的产出物）

- **文内步骤**：SKILL.md 中的有序动作。每一步都以明确的完成标准收尾。标准需可检查；必要时要求穷尽（如写“每个改过的 model 都已核对”）。含糊的标准是过早完成的主因
- **文内参考**：SKILL.md 内按需查阅的平级规则清单（本 skill 即属于纯文内参考）
- **外部文件**：从 SKILL.md 外移的参考或模板，正文留明确路径指引。同目录下为 skill 附属文件，跨 skill 共享另择位置

agent 是否读取外部文件取决于正文中指引的措辞。必读材料配上含糊的指引会导致随机失效：先优化指引措辞，仍无效再将内容收回正文

引用其他 skill 使用 `/skill-name`；引用内部文件使用相对路径 `[api.md](./references/api.md)`

同一概念的定义、规则需集中在同一标题下，避免散落

## 何时拆分

优先在 skill 内容按内容分层，外移参考和模板；拆分独立的 skill 是后手，拆分会产生新的上下文开销或认知负担。仅两种情况值得拆分：

- **需独立调用**：某块内容有自己独立的触发场景和引导词，或需要被其他 skill 调用
- **需隐藏步骤**：skill 内的后续步骤的存在会诱使 agent 抢跑，需要隔离隐藏

> 只有跨越真正的上下文边界（交给 subagent 执行或用户手动接续的 skill）隐藏才有效；在同一对话中调用另一 skill 隐藏无效

## 精简

- 每个含义只保留一个权威，保证 `SSOT` 修改行为时只需编辑一处
- 逐句检查相关性，删除无关内容（如在领域模型设计里写架构决策）
- 逐句做 no-op 测试，删除无默认行为改变的内容（如写模型默认就会执行的“请给出准确的答案”），删除冗余的解释性的内容（如已写 TDD 就不用再赘述“先写测试再写实现”）

仅有以下情况才额外解释或加禁令

- **非常规**：无合适的强锚定词，模型可能没有预训练或对常规有额外的解释
- **红线**：需要严格遵循，且要打破模型默认规则的情况（例如模型默认不遵循 TDD 或只遵循 水平TDD，而用户需要 垂直TDD 时可以加禁令，避免返工）

> 常规下使用正面描述目标行为，避免产生白熊效应（越叮嘱“别想白熊”，白熊越挥之不去）仅无法正面表述的硬性红线才用禁令，且必须配上替代行为

## 锚点词

锚点词是模型预训练中已有的紧凑概念，agent 执行时以它为思考锚点，用极少 token 锚定完整行为

- “要求先写测试再实现 → TDD”
- "don't think of an elephant → 白熊效应"

> 中英文锚点词选择根据“更精炼”、“共识更强”、“上下文适配性”权衡

## 行文规范

- 段落通读自然，用词追求通用，避免造生僻词
- 内容偏向书面语，避免口语（如写“随机失效”而非“时灵时不灵”）
- 中文使用全角标点，代码与纯英文语境保持半角；段尾省略句号

## 失败模式

- **过早完成**：步骤未完成即结束，注意力滑向“做完”。对策：先收紧完成标准；若标准无法再收紧且观察到抢跑，再拆分流程隐藏后续步骤
- **冗长**：篇幅过长，即便每行都有效。对策：按分支外移参考或拆分流程，让每条路径仅携带所需内容
- **重复**：同一含义写在多处，浪费 token，还会让该含义显得比实际更重要
- **no-op**：对模型输出无任何实质影响，是浪费 token 描述的无用指令
- **负面表述**：产生白熊效应，引起反作用
